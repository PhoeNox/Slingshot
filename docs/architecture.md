# Module map

Read the modules a change touches; skip the rest. Tests sit next to their module as `<module>.test.ts`. Domain terms are defined in `CONTEXT.md`.

## `src/core/`: deterministic simulation

Pure, seeded, no DOM, canvas, or clock (ADR-0001).

| Module | Responsibility |
| --- | --- |
| `match.ts` | Match state machine: `createMatch`, `step`, `adjustAim`, `fire` (only while aiming; returns the launched shot record), `startNextRound` (only during round over), `fireReceivedShot`, `nextShooter`, `previewShot`, read-only `matchView`; queries other modules ask instead of reading its state (the active side, a side's aim, the phase, whether this step streams aim, how long the round has been over) and `opponentOf` |
| `round.ts` | Round layout generation (ships, planets), `Ship`/`Planet`/`Aim` types, `BARREL_DISTANCE` |
| `flight.ts` | Body and missile physics: `moveBody` (gravity, planet contact, edge reflection under bounce, tracking) shared by missiles and debris; launch, ship collision (`flyMissile`), timeout, `STEPS_PER_SECOND` |
| `scoring.ts` | Round results, power penalty, next-round shooter |
| `zoom.ts` | View zoom per step: `nextZoom(previous, missile)` fits an out-of-area missile, leans toward its side, eases back |
| `attract.ts` | Self-playing demo match behind the main menu |
| `playingArea.ts` | Playing and tracking area bounds |
| `random.ts` | Seeded PRNG |

## `src/`: presentation and wiring

| Module | Responsibility |
| --- | --- |
| `main.ts` | Boot: queries elements, loads assets, builds the route adapters (injecting the browser peer connections and the Nostr reply relay into the host and guest screens), binds player input to the screen session and binds the screens, starts the loop |
| `routeController.ts` | Route entry in one place: draws the seed and takes the match rules, applies the route to the screen session, then the host and guest screens, then the shown screen; starts the remote match on handover under the seed and match rules drawn on that route entry; turns a step's `"mainMenu"` result into the main menu route; screen display, hash navigation and the host and guest screens are injected adapters |
| `gameLoop.ts` | Fixed 30 Hz step loop plus render callback |
| `screenSession.ts` | Current screen plus the one current `PlayedMatch` (hot-seat match, remote match or attract mode), which player input reads as `played`; entering a route keeps the played match if it is kept behind the new screen (attract mode between menu screens, with its debris) and otherwise leaves it, clears the debris and makes the new screen's played match in one place; steps it (a step reports `"mainMenu"` once the played match asks for the main menu) and advances the debris from the stepped view, composes the frame (match view for its viewer, then any notice) and the shake (only for a played match that shakes, never under reduced motion) without branching per mode; starts a remote match from the role, link, seed and match rules it is given and returns it; entering another remote match leaves the played match first |
| `playedMatch.ts` | The `PlayedMatch` interface every played match presents to the screen session (whether it takes player input, the aiming side, aim, fire, step, the match view to draw, the `Viewer`, whether it shakes, any notice, leave, the played match it stays as behind another menu screen), with the hot-seat and attract-mode adapters; the aiming side is the side player aim would set right now, or none (hot seat: the active player while aiming; a remote match: the local side only on the local turn); attract mode takes no input, ignores aim and fire, never shakes, steps only on screens that play it and is kept behind every menu screen, while a hot-seat or remote match is never kept (ADR-0002) |
| `remoteMatch.ts` | Remote match over an open `PeerLink`, from a role to the return to the main menu: the host plays left under the seed and match rules it is given, the guest plays right; decodes received text and feeds it, local aim and fire, steps and the link closing to the lockstep, then encodes and sends the messages it returns and closes the link on an ending; presented to the screen session as a `PlayedMatch` (`playRemoteMatch`) viewed from its local side, whose step asks for the main menu once the end notice has run out |
| `lockstep.ts` | Lockstep rules of a remote match, with no link, encoder or decoder: each event (start as host, local aim, local fire, a decoded or rejected message, a step, an ending) updates the lockstep state and returns the messages to send and the ending it reached; the host's hello, the guest building the match from it, local input only on the local turn, round starts only by the next shooter (through the match's `startNextRound`) and sent to the opponent, aim streaming of changed aims on the steps the match marks for it, opponent moves (aim, shot, round start) applied in order once the local flight has ended, outcome comparison, endings (left, opponent left, out of sync, version mismatch) with a leave sent unless the opponent left, the notice shown and when it has run out |
| `navigation.ts` | Hash routes (including the play menu, the host route and invitation routes carrying an offer code and a room secret), screens (the remote match has no route of its own: while it runs, the URL still shows the host route or the guest's invitation route, so reloading starts a new host or guest visit rather than resuming the match), which screens play attract mode (ADR-0002), menu focus movement (ADR-0003) |
| `screens.ts` | HTML menu/settings/credits overlays, button effects, settings tabs, one table-driven binder for every settings control (located by `data-setting` in the markup), route binding (ADR-0002) |
| `remoteVisit.ts` | Host and guest visit up to an open connection, without the DOM, as a thin driver over the visit transitions: starts the host or guest visit, performs each action they return (connect or join through the injected `PeerConnectors`, open the relay room, accept a reply code, deliver the reply, start and cancel the `REPLY_FALLBACK_MS` timer, show a `VisitState`, close a handle, hand the open link over with its role through the callback the route controller passes) and feeds every settled promise, relayed or pasted reply and timer tick back as an event, stale ones included; classifies failures into `PeerConnectionError` reasons or unexpected, and rethrows an unexpected failure from the promise (`settled` or `submitReply`) whose chain met it |
| `visitTransition.ts` | Visit rules of the host and the guest, with no connector, relay, timer or promise: each event updates the visit's progress and returns the actions to take; pending, then for the host the invitation (offer code and the room secret of the relay room it listens on) and connecting, for the guest joining (reply delivered through the relay) and the reply code fallback (shown once, when no relay accepted the reply or the fallback timer fired first, never after the link opened or the guest left), then handed over or failed; reply codes are taken only once the room is open, the first one, relayed or pasted, while it connects; the room closes on handover, a final failure or leaving; retry only after a rejected reply code (malformed, wrong kind, protocol mismatch) while still on the screen; a connection, room or link arriving after leaving is closed instead of adopted, and nothing is shown after leaving; an unexpected failure is rethrown |
| `remoteMatchScreens.ts` | DOM side of the host and guest screens: starts a visit per host or guest route and leaves the previous one, renders each `VisitState` (invitation link and reply code with copy buttons, reply code entry as the host's secondary option, status and failure messages per role) and passes reply code submissions to the host visit |
| `settings.ts` | Setting rule table (control kind, choices, labels, default, display vs match rule per setting) and the Settings type, defaults, parse/serialise of the stored form and match rules derived from it, stored-form match rules for the wire; planet count drag-along |
| `remoteProtocol.ts` | Remote match wire messages (hello, aim, shot, nextRound, outcome, leave): JSON encode, never-throwing decode with validation, `PROTOCOL_VERSION`, shot outcome comparison |
| `signalingCode.ts` | Compact, URL-safe signaling codes: a non-trickle offer or answer reduced to its connection fields (ICE credentials, DTLS fingerprint, setup role, candidates), deflated and base64url-encoded with the protocol version; never-throwing decode back to an SDP from a fixed data-channel template, rejecting garbage, wrong kind and version mismatch |
| `peerConnection.ts` | Browser `RTCPeerConnection` with one ordered, reliable data channel for host and guest: non-trickle offer and reply codes over public STUN only, a connect timeout after the host accepts a reply (the guest waits until its connection opens or fails) and a no-candidates failure as `PeerConnectionError`, and an open link to send and receive text plus a closed signal that fires once; connection factory injectable for tests; `HostPeerConnection` and `JoinPeerConnection` types for injecting the host and guest functions |
| `replyRelay.ts` | Carries the guest's reply code to the host through a fixed list of public Nostr relays (ADR-0004): the host opens a fresh room and subscribes to its tag on every relay, taking each reply once however many relays forward it; the guest seals and publishes its reply to every relay, `accepted` on the first relay acknowledgement or `unreached` when every relay rejected it, went away, or stayed silent for `RELAY_ACK_TIMEOUT_MS`; relay sockets are injectable for tests |
| `relayRoom.ts` | Room secret and the relay room derived from it with WebCrypto: the room tag relays filter on and AES-GCM sealing and opening, so relays see only opaque data; opening never throws |
| `nostrEvent.ts` | Nostr wire format for relay rooms: ephemeral room events signed by a throwaway Schnorr key (`@noble/curves`), publish and subscribe messages, never-throwing parse of relay acknowledgements and events |
| `settingsStorage.ts` | Reads and writes the stored settings in `localStorage`, tolerating unavailable storage |
| `input.ts` | Thin DOM adapter: passes key, touch and pen Pointer Events (overlay buttons excluded) and blur across the window to the player input, with the window's clock and timers; escape binding |
| `playerInput.ts` | Player input without the DOM: turns key down/up, pointer down/move/up/cancel, blur and repeat timer ticks into aim and fire on the current played match, through the key repeat and gesture rules and an injected clock; reports whether a key is consumed; a touch ends without firing once the match it started on is no longer played |
| `aimKeyRepeat.ts` | Held-key repeat rules for aim adjustment, behind `playerInput.ts` |
| `touchAim.ts` | Touch gesture rules, without the DOM, behind `playerInput.ts`: one pointer at a time, a tap below the drag threshold fires, a drag locks to its dominant axis (vertical raises or lowers the aiming side's barrel, toward the opponent adds power) and emits keyboard-sized aim steps per fixed CSS px, carrying the remainder within the drag; cancel, blur or leaving the match ends the touch without firing |
| `frameItems.ts` | Frame item vocabulary shared by frame description and the renderer: `FrameItem` (sprites, rings, lines, text, rects, groups), `Rect`, `Transform`, `SpriteName` |
| `frame.ts` | Turns a `MatchView` into `FrameItem` data for a `Viewer` (attract mode, hot seat, or a remote match's local side, giving You/Opponent labels and a turn line), plus the lockstep's `RemoteNotice`s; no drawing, no dependency on the remote match beyond that type |
| `renderer.ts` | Draws `FrameItem`s onto the canvas |
| `animationCurves.ts` | Afterglow, trail fade, explosion, round banner curves |
| `screenShake.ts` | Shake offset after hits |
| `debris.ts` | Cosmetic impact particles: advancing from a match view, bursts, motion via core `moveBody`, splitting on planets, fade-out; state and unseeded randomness stay outside the core |
| `stars.ts` / `starLayer.ts` | Star field generation / drawing |
| `display.ts` | Fits canvas and overlay to the window |
| `assets.ts` | Sprite and font loading |
| `colours.ts` | Colour tokens |
| `scramble.ts` | Menu label scramble effect |
| `shipHits.test.ts` | End-to-end check: seeded matches through the screen session register ship hits |
| `lockstep.test.ts` | Unit checks of every lockstep rule, peers relayed in-process without a link |
| `visitTransition.test.ts` | Unit checks of every visit rule, synchronous, without connectors, relay or timers |
| `remoteMatch.test.ts` | End-to-end check: two screen sessions over an in-memory channel play a remote match in lockstep and drive each ending through to the main menu step result |
